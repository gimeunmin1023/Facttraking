# FactTrace

사건 진술을 원자 단위로 쪼개 기록하고, 화자 내부·화자 간·물증 대조를 규칙으로 판정해
5축 평가와 조사 우선순위를 산출한다.

`index.html` 하나로 동작한다. 서버·빌드·API 키·네트워크가 필요 없다.

```
index.html                 앱 전체 (엔진 + UI)
samples/case-money.json    검증용 사건: 세 진술자가 현금 위치를 다르게 말한다
tests/run.js               node tests/run.js — 39건 검증
tests/fixtures/            구버전 내보내기 회귀 데이터
```

## 왜 다시 만들었나

이전 버전이 모순을 놓친 것은 규칙이 모자라서가 아니라 구조 때문이었다.

| 이전 | 지금 |
|---|---|
| 분석 결과가 화자별로 격리돼 있어 A·B·C 사이를 비교하지 않았다 | 모든 화자 쌍을 교차 대조한다 (R2·R3) |
| `object`/`location` 문자열이 완전히 같아야 매칭됐다 | 별칭 사전 + 위치 포함 트리로 정규화한다 |
| 상태 진술("돈이 서랍에 있었다")을 담을 자리가 없었다 | `kind:'state'` 로 분리해 저장한다 |
| 복문을 claim 1개로 삼켜 뒤쪽 행위가 사라졌다 | 연결어미에서 절을 분해한다 |
| 절을 따로 파싱해 지시어·생략 주어를 못 이었다 | 문맥 상속 레이어를 두고 추론분을 표시한다 |
| 1·2단계 평가가 출력에 없었다 | 5축 점수 + 근거 claim 링크 |

## 쓰는 법

1. `index.html` 을 브라우저로 연다.
2. **INGEST** — 화자·회차를 고르고 진술을 그대로 붙여넣고 `원자화`.
3. **ATOMS** — 자동으로 채워진 슬롯을 확인·수정한다. 시간 구간은 채워야 R4·R6가 돈다.
4. **CONFLICT** — 심각도순 모순 목록. 좌우로 원문을 대조한다.
5. **ASSESS** — 화자별 5축 점수와 조사 우선순위.

`Import` 는 구버전 내보내기(`action`/`object`/`location` 스키마)도 그대로 읽는다.

## 문맥 처리

절을 따로 뜯으면 "거기서 그걸 꺼냈다" 같은 절은 슬롯이 텅 빈다. 세 갈래로 이어붙인다.

| 표현 | 처리 |
|---|---|
| 거기 · 그곳 · 그쪽 · 그 자리 | 앞선 원자의 장소를 상속 (문장을 넘어서도) |
| 그것 · 그거 · 그걸 · 이거 | 앞선 원자의 대상을 상속 |
| 걔 · 그 사람 · 그분 · 본인 | 앞서 언급된 인물을 상속하고 `observation` 으로 전환 |
| 지시어 없이 장소가 빈 절 | **같은 문장 안에서만** 상속 |

상속한 슬롯은 `inherited` 에 남고 화면에 붉은 점선으로 표시된다.
그 위에 선 모순 판정은 심각도를 0.7배로 깎는다. 진술자가 하지 않은 말을 근거로
강한 판정을 내리면 안 되기 때문이다. 사람이 값을 한 번 만지면 확정으로 바뀐다.

지켜야 할 경계가 셋 있다.

- **목격·상태 진술의 장소는 화자 위치로 새지 않는다.** "B는 소파에 있었다" 다음의
  "저는 나왔습니다" 가 소파를 물려받으면 없는 동선이 만들어진다.
- **생략된 목적어는 상속하지 않는다.** "봉투가 있길래 다시 닫았습니다" 에서 닫은 것은
  봉투가 아니라 서랍이다. 지시어가 있을 때만 이어받는다.
- **입·퇴실은 앞 장소를 끌어오지 않는다.** 그 자체로 출입구를 함의한다.

지시대명사는 가장 최근 언급을 가리킨다고 본다. 지시 대상이 그보다 앞을 가리키면
틀리므로, 붉은 점선이 뜬 슬롯은 눈으로 확인해야 한다.

### 절 분해

연결어미에서 절을 가른다 — `-가서 -와서 -아서 -어서 -고 -고서 -면서 -자마자 -다가
-길래 -느라 -는데 -지만 -ㄴ다음 -ㄴ뒤 -ㄴ후`. 어미는 왼쪽 절에 남겨 서술어 판정을
살린다. 접속 부사(`그리고`, `그 다음에` …)는 같은 길이의 공백으로 덮어 들어낸다 —
잘라내면 "그 다음에 창가로" 가 "에 창가로" 로 깨진다.

서술어는 **끝나는 위치가 뒤인 것**을 고른다. 시작 위치로 재면 '들어갔다' 의 `갔` 이
`들어가` 를 이겨 입실이 이동으로 뒤집힌다.

### 시간

시간 표현은 절이 갈라지면서 다른 조각으로 떨어지므로 **문장 단위**로 잡아
`timeHint` 에 붙인다("5분", "6시"). 다만 `startSec`/`endSec` 는 **자동으로 채우지 않는다.**
없는 시각을 지어내면 R6의 미설명 시간이 0으로 나와 "모두 해명됨" 처럼 보인다.
붙여넣기만 한 상태에서는 R4·R6가 돌지 않으며, ATOMS 상단에 그 사실을 띄운다.

## 원자 하나의 구조

```js
{
  id, speaker, round, quote,
  kind:      'action' | 'state' | 'observation' | 'denial',
  predicate: '이동' | '접근' | '접촉' | '개폐' | '획득' | '은닉'
           | '목격' | '부재' | '내려놓음' | '확인' | '정리' | '입실' | '퇴실',
  entityId, locationId,     // 정규화 ID
  actorId,                  // observation 일 때 "누구를 봤는가"
  startSec, endSec,
  polarity:  'yes' | 'no',
  modality:  'assert' | 'hedge',
  scope:     'interval' | 'session',   // 부인은 보통 세션 전체를 뜻한다
  sourceType:'statement' | 'evidence',
  verifiable, stateBefore, stateAfter
}
```

`kind` 가 무엇이냐에 따라 `locationId` 가 가리키는 대상이 다르다.

- `action` · `denial` → **화자 본인**이 있던 곳
- `state` · `observation` → **대상 물건 또는 지목당한 사람**이 있던 곳

이 구분이 없으면 "내가 창가에 있었다"와 "돈이 창가에 있었다"가 같은 자리에 들어가
교차 대조가 불가능해진다.

## 모순 규칙

| 규칙 | 조건 | 기본 가중 |
|---|---|---|
| R1a | 같은 화자가 같은 구역에 대해 한쪽은 부인, 한쪽은 그 구역에서의 행위 | 1.0 |
| R1b | 같은 화자, 같은 술어·대상, 극성 반전 | 1.0 |
| R2 | **서로 다른 화자가 같은 물건을 서로 떨어진 구역에 둔다** | 1.0 |
| R3 | **목격 진술과 지목당한 본인의 진술이 반대** | 1.0 |
| R4 | 같은 화자가 겹치는 시각에 서로 떨어진 두 구역에 | 0.9 |
| R5 | 상태 전이가 진술 없이 끊긴다 | 0.5 |
| R6 | 사건 시간 중 어떤 진술로도 채워지지 않은 구간 | 0.5 |
| R7 | 위 판정의 한쪽이 물증이면 심각도 2배, 규칙명에 `/R7` | ×2 |

```
sev = 기본가중 × 시간겹침 × (물증 ? 2 : 1) × (추측 진술이면 0.6)
hard ≥ 0.80   medium ≥ 0.40   soft < 0.40
```

**책임 배분(blame).** 목격했다는 이유로 목격자가 깎이면 안 된다.

- R3 — 지목당한 쪽 1.0, 목격한 쪽 0.3
- R2 — 같은 물건에 대해 다수가 합의한 위치를 말한 화자 0.3, 소수 위치 1.0

**부인의 범위.** "만지지 않았다"는 접촉의 부인이지 그 자리에 없었다는 뜻이 아니다.
위치를 다투는 술어(`이동`·`접근`·`입실`·`퇴실`)만 R1a·R3의 위치 부인으로 읽는다.

## 평가 공식

**1단계 · 진술 구조**

```
객관성 O = 100 × (1 − 추측비율×0.6 − 전언추측비율×0.4)
일관성 C = 100 × exp(−Σ내부모순sev / 3)
통일성 U = 100 − 100 × (반전×2 + 신규×0.5) / 전체키수
```

**2단계 · 진술 내용**

```
구체성 S = 100 × (슬롯충족×0.4 + 검증가능비율×0.3 + 시간정밀도×0.3)
개연성 P = 100 × exp(−Σ(교차모순sev × blame) + 물리위반×0.5) / 2.5)
```

**조사 우선순위**

```
Suspicion = [ 2.0(100−U) + 1.5(100−C) + 1.5(100−P)
            + 1.0·미설명시간비율 + 1.0(100−S) + 0.5(100−O) ] / 8.5
```

통일성에 가장 큰 가중을 둔다. 회차 사이에 말이 뒤집히는 것이
단발 모순보다 강한 신호이기 때문이다.

**이 점수는 범인 확정이 아니라 조사 우선순위다.** 진술 구조에서 관찰되는 이상치의
순위이고, 근거가 되는 claim id 를 항상 함께 낸다. 근거를 열어 원문을 확인하지 않은
채로 순위만 인용하면 안 된다.

## 물증 넣는 법

CCTV·포렌식 같은 물증은 **대상자를 `speaker` 에 적고** `sourceType` 을 `evidence` 로 둔다.
그러면 그 사람의 진술과 같은 화자 규칙(R1a·R1b)으로 대조되고 심각도가 2배가 된다.

```json
{ "id": "B9", "speaker": "B", "sourceType": "evidence",
  "kind": "action", "predicate": "접촉", "entityId": "E_DRAWER",
  "locationId": "L_DRAWER", "startSec": 95, "endSec": 130,
  "quote": "CCTV: 서랍을 열고 손을 넣는 동작이 확인됨." }
```

## 사전 확장

`index.html` 안의 `LOCATION_SEED` 와 `ENTITY_SEED` 를 사건에 맞게 고친다.
위치는 `parent` 로 포함 관계를 만든다 — 조상·자손이면 같은 구역, 아니면 떨어진 구역이다.

```js
L_DESK   : { name:'교수 책상', parent:'L_ROOM', aliases:['책상','책상 쪽','책상 옆'] },
L_DRAWER : { name:'책상 서랍', parent:'L_DESK', aliases:['서랍','서랍 안'] }
```

진술에 없던 물건이 나오면 ATOMS 상단 트레이에 쌓이고, 유사도 상위 3개를 제안한다.
자동 병합은 하지 않는다 — 개체 동일성 판단은 사람이 한다.

## 검증

```bash
node tests/run.js
```

`index.html` 의 엔진 블록을 그대로 떼어내 돌리므로 코드가 이중화되지 않는다.
브라우저 콘솔에서는 `__selftest()` 로 같은 것을 돌린다.

- 자가검증 25건 — 정규화·절 분해·문맥 상속·R1a~R7
- 회귀 8건 — 구버전 내보내기 14 claim 을 승격해 기존 판정(B2↔B5 모순, B 미설명 50초)이 그대로 나오는지
- 시나리오 6건 — 세 진술자의 현금 위치 불일치를 R2가 hard 로 잡는지
