# FactTrace Gaze

녹화한 진술 영상에서 진술자가 **어느 구역을 언제, 얼마나 오래 봤는지** 뽑는다.

설치할 것이 없다. 모델과 라이브러리가 이 폴더에 들어 있어 인터넷 없이 돌아간다.

## 실행

- **Windows** — `start.bat` 더블클릭
- **macOS · Linux** — `start.command` 더블클릭 (또는 `sh start.command`)

브라우저가 열린다. 창을 닫으면 끝난다.

> `index.html` 을 더블클릭하면 **동작하지 않는다.** 브라우저가 `file://` 에서는
> 모델 파일을 읽지 못하게 막기 때문이다. 위 스크립트는 그 때문에 있는 것이고,
> 하는 일은 이 폴더를 `localhost` 로 띄우는 것뿐이다. 영상은 밖으로 나가지 않는다.

파이썬이 없다는 메시지가 나오면 [python.org](https://www.python.org) 에서 설치하면 된다.

## 쓰는 법

1. **SOURCE** — 영상을 고르고 화자·회차를 적는다.
2. **CALIBRATE** — 영상을 재생하다 진술자가 **한 곳을 계속 보고 있는 구간**을 찾아
   구역 이름을 적고 `시작 표시` → `끝 표시`. **구역 두 개 이상**, 구간마다 1초 이상.
3. **RUN** — `분석 시작`. 진행률과 남은 시간이 나온다.
4. **RESULT** — 구역별 응시 시간과 시간 띠.
5. **Export** — JSON 으로 내보낸다.

캘리브레이션이 곧 설정이다. 촬영할 때 **시작 전에 각 지점을 3초씩 쳐다보게 해 두면**
그 구간을 그대로 쓰면 되니 가장 편하다.

## 왜 캘리브레이션인가

무료 웹캠 시선 추정의 정확도가 무너지는 지점은 **절대 시선 각도**다. 사람마다 눈
모양이 다르고 카메라 위치도 매번 달라, 보정 없이 "몇 도를 보고 있다" 를 맞히려 하면
4° 안팎의 오차가 그대로 남는다.

그래서 이 도구는 **절대 각도를 추정하지 않는다.** 대신 "이 사람이 이 카메라 앞에서
저기를 볼 때 눈이 이렇게 생겼다" 를 구간에서 배우고, 나머지 프레임을 거기에 견준다.
사람·카메라·조명이 바뀌어도 캘리브레이션만 다시 하면 된다.

특징은 6차원이다 — 양쪽 눈에서 홍채가 눈 안 어디에 쏠렸는지(4), 머리의 좌우·상하
방향(2). 얼굴 크기로 나눠 두어 카메라와의 거리가 변해도 흔들리지 않는다.

## 결과를 못 믿어야 하는 경우

프로그램이 스스로 알려 준다.

- **얼굴 검출 80% 미만** — 조명·거리·가림 문제다. 다시 찍는 편이 낫다.
- **구역이 겹칩니다** — 두 구역이 시선상 너무 가까워 구별되지 않는다.
  더 떨어진 지점으로 잡거나 하나로 합쳐야 한다.
- **미상 비율이 높음** — 캘리브레이션에 없는 곳을 보고 있었다는 뜻이다.
  빠진 구역을 추가하면 준다.

애매한 프레임은 **배정하지 않고 미상으로 남긴다.** 1등과 2등 구역이 비슷하게 가까우면
어느 쪽인지 말할 수 없으므로, 억지로 고르지 않는다.

## FactTrace 에 붙일 때

내보낸 JSON 의 `sourceType` 은 `evidence` 가 아니라 **`gaze`** 로 둘 것.
그리고 **용의도 랭킹에 합산하지 말 것.**

시선 회피는 거짓말의 지표가 아니다. 가장 널리 믿기는 단서지만 메타분석에서 진단
가치가 거의 0에 수렴한다(DePaulo et al., 2003). 검증되지 않은 점수를 순위에 섞으면
FactTrace 가 지키는 "모든 판정에 근거를 단다" 는 원칙이 깨진다.

쓸 만한 쪽은 **통제된 자극에 대한 응시** 다 — 여러 물건·장소를 보여줬을 때 사건과
관련된 항목을 먼저, 오래 보는가. "긴장했는가" 가 아니라 "알고 있는가" 를 보는 것이라
논리가 방어된다.
